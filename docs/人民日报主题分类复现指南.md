# 人民日报八类主题分类复现指南

分类语料来自人民日报9801—9803；主题由DeepSeek单次自动标注。原生FastText比较随机与预训练初始化，另有三种冻结表示接同一LinearSVC的实验，二者复用相同标签和划分，分别保存、解释。线性Softmax不在当前实验范围内。

## 环境与入口

在项目根目录 `C:\Projects\LLM\Gensim` 使用 conda 环境 `Gensim`（Python 3.12）。原生训练默认20个CPU线程，数值库4线程，配置见 [runtime.yaml](../configs/runtime.yaml)。FastText 采用当前环境已安装的 `fasttext-wheel==0.9.2`，保存完整版本快照。多线程随机训练不保证重新运行逐位一致；同一保存模型加载后的预测须一致。

## 准备与标注

```powershell
conda run -n Gensim python -m gensim_lab.pfr_topics prepare
# 首次运行需通过进程环境提供 DEEPSEEK_API_KEY，不将密钥写入项目文件

```

原始数据位于 `data/raw/199801.txt`、`199802.txt`、`199803.txt`。聚合文章后删除编号、词性和实体标记，保留原分词，不另删停用词；清除控制字符并统一全半角。少于30个有效词的文章排除，完全重复文本留最早一篇，近重复用字符三元组 SimHash 距离≤3分组。给标注接口的文本保留标点和段落，提交匿名ID，不提交版号或旧标签。

主题固定为政治、财经、科技、体育、娱乐、社会、军事、国际；完整判定范围和边界见 [实施方案](人民日报八类主题分类实施方案.md)。无法归类的文章保留原因，退出分类实验；有歧义但可以确定主主题的文章保留歧义标记并进入实验。

标注并发20、每批最多4篇，预算35元。每篇成功结果只保存一次；只对结构、遗漏、证据格式及网络失败重试，最多两次。成功记录在恢复时复用，不重复付费。费用按响应 `usage` 和调用时段逐请求核算。未知用量失败按预算预留上界记录，不隐去失败请求。

若已有响应仅因引用格式未通过校验，可执行：

```powershell
conda run -n Gensim python -m gensim_lab.pfr_topics recover
```

此入口只读取历史响应，保留其主题判断，截取实际连续原文或缩短过长证据，不调用接口。原始引用、修复标记和恢复审计均保存。退出分类的 `out_of_scope` 记录允许显式缺少证据；进入分类的记录必须有真实连续引用。全部文章成功后才封存 `annotation_seal.json`，模型训练会校验文章、标签及请求日志的 SHA-256。

## 分类训练与选轮

```powershell
conda run -n Gensim python -m gensim_lab.pfr_topic_native prepare
conda run -n Gensim python -m gensim_lab.pfr_topic_native run
```

当前清洗后8,431篇完成标注，进入分类共8,063篇：一、二月训练5,333篇，三月验证820篇、测试1,910篇。三月按主题分层、近重复组划分，种子42，目标30%／70%。检查文章ID、完全相同文本及近重复组均不跨分区。此划分称“三月留出测试”，三月验证部分确实参与选参。

分组顺序先按种子42生成哈希排序，再用 `StratifiedGroupKFold(shuffle=False)` 分配10折，其中3折验证、7折测试。这样避免当前 scikit-learn 1.7.2 内部打乱计数却不同步组索引的问题。正式结果使用修正后的分区；首次划分的模型单独保留并标为已替代。修正只依据划分比例和实现核验，未依据测试分数调整配置。

两条路线均为100维、学习率0.1、minCount=1、词bigram、关闭字符子词、softmax、200,000桶。训练输入每篇一行，使用 `__label__t0`—`__label__t7` 匿名主题标签。输入不含原始编号或词性。

预训练来源为已封存的 [Gensim FastText 运行](../artifacts/thucnews_validation/runs/31fd3e9423f08bd77a62e68d/summary.json)。只导出本轮训练词表，源词表外的训练词允许使用Gensim子词生成向量。原生模型加载完整词向量，不加载Gensim字符子词桶；监督训练更新输入向量副本和分类输出层，不改源模型。学习率为零的探针核验实际导入值，另保存监督训练前后检查词的向量变化。

种子42分别从头训练5、15、25、50、100、200轮，仅计算验证指标，按验证Macro-F1选轮；并列优先少轮。每条路线在选定轮数补种子2026、7，共16次训练、6个最终模型。六档点是独立训练终点，不能称逐轮连续曲线。若选中上界200轮，只能说明在已测预算中最好，不能据此证明收敛或全局最优。

`selection_frozen.json` 先冻结配置，再统一测试。保存Accuracy、Macro/Micro/Weighted-F1、逐主题PRF、混淆矩阵、逐篇预测概率、训练耗时、进程峰值RSS及模型大小。三种子样本SD衡量监督训练波动，2,000次主题分层配对bootstrap衡量种子42模型的测试文章抽样差异，二者分别报告。

已封存的候选按数据、标签、配置、输入向量和协议指纹校验后复用。修改配置会生成独立实验目录，不覆盖已有模型。

```powershell
conda run -n Gensim python -m gensim_lab.pfr_topic_native predict --run artifacts/pfr_topics/experiments/实验指纹/runs/运行指纹 --tokens '球队 获得 比赛 冠军'

conda run -n Gensim python -m gensim_lab.pfr_topic_native predict --run artifacts/pfr_topics/experiments/实验指纹/runs/运行指纹 --text '球队获得比赛冠军。'
```

输出八类中文主题和原生softmax分数；此分数未进行概率校准。精确重现已有样本应传入其已保存tokens。保存／加载核验检查预测标签和分数逐位一致，指标可从CSV逐篇预测重新计算。

FastText 0.9.2 的预测路径使用 `log(p + 1e-5)`，接口返回值存在数值偏移，可能略大于1。概率出口取完整八类分数，减去此偏移、截除浮点舍入负值并归一化，保证各项在0—1之间且和为1；此处理保持主题排序，不属于概率校准。逐篇CSV同时保存 `raw_native_score` 和规范化后的 `score`，依据见本项目固定的 [loss.cc](../references/sources/fastText-0.9.2/src/loss.cc)。

## 三种冻结表示与同一LinearSVC

配置见[pfr_topic_svm.yaml](../configs/pfr_topic_svm.yaml)。TF-IDF使用既有50,000词词典和IDF；Word2Vec为300维；Gensim FastText为100维，允许生成未登录词子词向量。后两者按词出现次数加权求均值；所有文章向量做L2归一化。表示不重新拟合，主题不重新标注，因此不需要接口密钥、没有新增标注费用。

三种表示统一使用LinearSVC（balanced类别权重、L2惩罚、squared-hinge、one-vs-rest、dual=False、tol=1e-4）。训练仅用一至二月5,333篇，验证用三月820篇，C={0.1,1,10}按验证Macro-F1选择，冻结后测试三月1,910篇。每组凸优化求解一次；测试文章配对bootstrap区间不代表预训练种子波动。liblinear使用CPU；数值库4线程，特征转换8线程，不把此求解器描述为CUDA或20线程训练。

```powershell
conda run -n Gensim python -m gensim_lab.pfr_topic_svm prepare
conda run -n Gensim python -m gensim_lab.pfr_topic_svm run
conda run -n Gensim python -m gensim_lab.pfr_topic_svm audit
conda run -n Gensim python -m gensim_lab.pfr_topic_svm predict --method tfidf --tokens '球队 获得 比赛 冠军'
conda run -n Gensim python -m gensim_lab.pfr_topic_svm predict --method word2vec --text '球队获得比赛冠军。'
conda run -n Gensim python -m gensim_lab.pfr_topic_svm predict --method fasttext --tokens '球队 获得 比赛 冠军'
```

预测返回八类中文主题和各类别decision_function分数，分数可能为负，不能当作概率。已有文章通过原tokens复现；新文本的jieba分词与原始语料标注规范可能不同。

LinearSVC不提供逐epoch回调。准确率曲线使用各自已选C，分别从头拟合max_iter=1—20的求解预算，每预算保存模型、实际n_iter、收敛状态及完整验证预测。不在诊断中调用测试集；预算20与正式模型的验证预测和决策分数完全一致。较低预算的未收敛警告是诊断的一部分，不能将这些模型称为已收敛正式结果。图的横轴是求解迭代预算，连线不代表单次训练的epoch轨迹。

```powershell
conda run -n Gensim python -m gensim_lab.pfr_topic_svm_iterations
conda run -n Gensim python -m gensim_lab.pfr_topic_svm_report preview
# 逐张检查彩色和灰度预览，通过后写入与图像指纹一致的visual_review.json
conda run -n Gensim python -m gensim_lab.pfr_topic_svm_report export
conda run -n Gensim python -m gensim_lab.pfr_topic_svm_report publish

```

资源根目录为`artifacts/pfr_topic_svm`，`latest.json`定位完整实验；求解诊断目录由实验内`iteration_diagnostic/latest.json`定位。训练索引、配置、源模型指纹、特征、逐篇预测、九组验证和三组测试指标均独立封存。图导出PNG／SVG／灰度PNG，发布只改1.2并保留用户编辑的1.1和part2。结果见[LinearSVC独立报告](../reports/人民日报三种表示LinearSVC对比.md)和[提交报告](../reports/Gensim&FastText.md)1.2.6。
