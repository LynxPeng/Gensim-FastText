# 论文阅读与源码分析

本分析固定 Gensim 4.4.0 和 FastText 0.9.2。源码逐文件归档、版本来源和 SHA-256 见[源码清单](../references/source_manifest.json)，可点击的函数行号见[源码位置索引](源码位置索引.md)。解释结合[运行探针](运行核验证据.md)、[参数实验](参数分析.md)和每个运行目录的日志、数组及预测记录。

Gensim 的九个归档文件来自实际安装的 Windows wheel，已与官方 4.4.0 标签逐文件核对：统一 CRLF/LF 换行后文本完全一致。清单同时保存本地和上游原始字节 SHA-256，避免把换行造成的字节差异误判为代码差异。FastText C++ 阅读副本直接来自官方 v0.9.2 标签。

## 两篇论文的任务不同

Piotr Bojanowski、Edouard Grave、Armand Joulin、Tomas Mikolov，2017，*Enriching Word Vectors with Subword Information*，TACL 5:135–146，DOI [10.1162/tacl_a_00051](https://doi.org/10.1162/tacl_a_00051)。重点读第 3.1–3.2 节（136–137 页）的目标与子词、第 4.2–4.3 节（138 页）的优化以及第 5.5 节（141–142 页）的长度对照。词的字符片段共享参数，用上下文正例和随机负例学习。未登录词可组合子词；论文的欧语长度设置和评测任务需要通过本项目中文版面验证集重新检验。[论文原文](https://aclanthology.org/Q17-1010.pdf)

Armand Joulin、Edouard Grave、Piotr Bojanowski、Tomas Mikolov，2017，*Bag of Tricks for Efficient Text Classification*，EACL Short Papers:427–431。ACL 元数据未提供 DOI，因此不填入。重点读第 2 节（427–428 页）的监督目标、第 2.1 节的层次 softmax 和第 2.2 节的词 n-gram。词和相邻词组合形成文章特征，平均后直接预测标签；输入表示与分类参数一起由标签损失更新。大标签空间可用树形目标提速，本项目 12 类使用计划指定的普通 softmax。[论文原文](https://aclanthology.org/E17-2068.pdf)

本项目复现实现机制与参数对照，并在当前中文语料上完成下游版面分类。后续补充真实中文词相似度和类比基准，使用 Gensim 内置接口保存相关系数/p 值、OOV、总体与分关系类比准确率；Word2Vec 重训保存逐轮 loss，并补充 HS 逐句 score 与数值复算。完整口径和结果见[词向量全面评价报告](词向量全面评价报告.md)。没有声称复现两篇论文的全部外文数据与原论文数值。

两条路线的优化预算和类别处理也不同：原生 supervised 通常每篇文章做一次标签损失更新，Gensim 表示训练产生许多词—上下文更新，再由 SVM 学标签；相同 epoch 数不代表相同更新次数。SVM 使用 balanced 类别权重，原生监督没有额外重加权。观察 Macro-F1 差异时，需要同时考虑这些流程差异，不能全部归因于“有没有子词”。

| 比较 | Gensim FastText + LinearSVC | 原生 FastText 监督分类 |
| --- | --- | --- |
| 表示学习目标 | 词到上下文；无监督，只用当前训练文章 | 文章到版面标签；监督 |
| 子词 | 主配置字符 1–3；词内 UTF-8 字符片段 | 主配置关闭字符子词，保留词 bigram |
| 文章表示 | 训练完词向量再均值/IDF 加权、L2 归一化 | 内部输入特征平均；不采用本项目的外部 L2 流程 |
| 分类器 | 独立训练的类别权重 LinearSVC，验证选择 C | 标签输出矩阵与输入矩阵联合训练，softmax |
| 输出分数 | SVM 决策边距 | softmax 近似概率；源码存在数值平滑，不视为校准概率 |
| OOV | 通过哈希子词生成向量，可能包含未训练桶 | 单词字符向量关闭时无 OOV 单词向量；含未知词的词 bigram 仍可能产生哈希特征 |

## 子词、哈希与覆盖率的细节

训练实际使用 `compute_ngrams_bytes`，不能拿另一个简单字符串 `compute_ngrams` 的输出当作完全等价结果。前者给词加 `<`、`>`，跳过 UTF-8 后续字节，按字符计数，不保留单独的边界一元组。对中文两字词，1–3 可以共享单个汉字和词首/词尾片段，3–6 的很多片段反而接近整词。哪一组更适合版面分类应由验证实验决定。

论文称 FNV-1a，但固定版本为了历史模型兼容，逐字节先转有符号 int8 再异或到 uint32，乘法以 32 位溢出。对中文 UTF-8 字节，直接用通常的 unsigned-byte FNV 可能产生不同桶。运行探针按这个兼容规则独立实现并比对；Python 内置 `hash()` 不是子词哈希，也不能代替它。

每个已登录词先缓存桶编号列表 `buckets_word`。训练更新独立的 `vectors_vocab` 和 `vectors_ngrams`，结束后 `adjust_vectors` 生成可查询的组合向量。已登录词取整词行加子词行并除以片段数加一；OOV 没有整词行，只平均所有片段桶。重复桶编号可以多次贡献，不能擅自对每个词的桶列表去重。

碰撞率定义为 `1 − 不同子词占用桶数 / 不同 UTF-8 子词数`，不是“每次查找出错的概率”。同子词在许多词里出现是正常共享，只有不同子词映射同桶才计碰撞。统计来自训练词表，不使用验证/测试文本。桶数增大通常减少碰撞，但分类指标也受随机初始化及正则化影响，不能把一次分数变化直接认定为碰撞因果。

`word in model.wv` 在启用子词时可能对 OOV 返回真，所以工程通过 `wv.key_to_index` 统计真正词表内外。OOV 向量覆盖只检查是否可生成有限、非零向量；即使所有片段从未训练过，初始化桶也可能给出非零结果。覆盖达到 100% 不等同于语义准确率 100%。

关闭子词后，Gensim 将有效桶数设为零，OOV 查询会抛 KeyError；聚合器跳过它并统计零向量文章。原生监督 bigram 的桶用途不同：它对相邻词哈希做递推，即使未知单词没有字符向量，该词仍可参与组合特征。因此报告把“单词 OOV 向量覆盖”和“监督特征完全覆盖”区别解释。

## 过滤、目标和下采样

TF-IDF 的 `no_below` 是文档频次，Word2Vec/FastText 的 `min_count` 是 token 出现次数。词典同时执行 `no_above=0.9`，词向量词表没有这项文档占比过滤。两套词表是有意采用的表示机制，报告的 OOV 以对应方法实际使用的词表为准。

负采样的累积分布默认 `ns_exponent=0.75`，与子词论文实现段采用的平方根频次分布不同；本工程保留计划中的 Gensim 默认。负采样 10 增加每个正例的计算，层次 softmax 走词频 Huffman 路径；同时打开两种目标会训练两个输出，本实验 hs 对照明确关闭负采样。

Gensim 对频词设置 `sample_int`，训练时随机决定是否保留；功能词仍在清洗文本、词表和文章聚合中存在。探针分别记录 sample=0/0.001 的有效训练词数。原生 `Dictionary::discard` 在监督模式直接返回 false；不能把无监督下采样参数的作用直接搬到原生监督分类。

## 学习率、迭代、队列与线程

Gensim 的任务生产线程累积完整句子，接近 `batch_words` 后把 `(sentences, alpha)` 放入有界队列，工作线程取任务并使用每线程的工作数组。句子超过任务上限时可能使任务超过设定值，因此工程先将极长句分为最多 1000 词的上下文。这个参数主要控制工作调度，不是神经网络意义上把多个样本梯度平均后才更新的 mini-batch。

学习率按 epoch 和已排入任务的例数/词数线性下降并受 min_alpha 下限限制。改变 batch_words 会改变 alpha 更新的粒度，即使单线程也可能改变浮点结果和分类分数。原生 `trainThread` 用全局 tokenCount 的进度衰减，局部 token 计数达到 lrUpdateRate 后才上报；不能按文章条数简单换算成完全一致的优化轨迹。

词表构建和每一轮训练都需要重新遍历语料。一次性生成器耗尽后会导致后续轮无数据；本项目 `SentenceCorpus.__iter__` 每次从文章的句子列表开始。Doc2Vec 则以文章 TaggedDocument 训练 DBOW，评估时所有分区统一 `infer_vector(epochs=30)`，不用训练文章缓存的标签向量作为更有利的特征。

后续审查发现按编号重置推断随机状态会使相同文本更换编号后改变结果。当前 Doc2Vec 通过[内容种子协议](../gensim_lab/content_seed.py)按 token 序列 SHA-256 生成稳定种子，并对全部未登录词文章输出零向量，避免将没有学习更新的随机初始化当作有效文本向量。受影响实验已重训，版本和适配器源码 SHA-256 保存在 spec；历史旧模型保留，详见[补充验证](补充实验与改进报告.md)。

Gensim Python 层负责队列、数据编码及调度，Cython 中 `train_batch_any` 在 `nogil` 区域执行数值内核。原生 Python 包将参数传给 pybind，绑定的 train 释放 GIL，C++ 建立共享输入/输出矩阵并启动线程。异步更新顺序使多线程难以逐位复现；速度试验的验证分数只作为现象，不参与正式参数选择。

线程数不是越多越快。当前语料较小，Python 数据准备、子词访问和同步成本可能限制收益；正式资源表提供实际训练秒数，线程对照见参数报告。任务只顺序启动，减少多个训练同时争夺资源；采样峰值是该工作进程的 RSS，50ms 采样可能漏掉极短峰值。

## 内存、保存与跨语言边界

Gensim 主要浮点矩阵为 float32：整词输入 V×d、组合查询 V×d、子词 B×d，负采样输出通常 V×d；还包括桶列表、词典、分类器与语料对象。仅子词表约 `4Bd` 字节，200k×100 约 76.3 MiB，1m×100 约 381.5 MiB。模型文件大小和进程 RSS 含不同对象，不应相互替代。关闭子词时无需该桶矩阵。

原生输入矩阵常为 `(词数+桶数)×d`，输出 softmax 矩阵为 `类别数×d`；关闭字符子词但使用词 bigram 时仍需桶。连续 DenseMatrix 用行访问，Python 的矩阵获取可能产生副本，探针只在小模型执行。原生矩阵初始化也在固定 `densematrix.cc` 中，版本和线程可能影响初始值；本项目不假设第三方 Windows wheel 与阅读的上游源码逐字节相同。

Python 包的 `_build_args`（FastText.py:427–428）会在 `wordNgrams≤1` 且 `maxn=0` 时把实际 bucket 改成 0，即使配置记录仍保存用户传入的 200,000。因此 unigram 对照的模型明显较小是可解释的实现行为；选定原生模型的运行时参数另在 error_diagnosis.json 记录，不能只按输入配置估计它的实际桶内存。

工程用 joblib 保存包含训练词典、IDF、表示及 SVM 的 Bundle；原生 C++ 模型另外保存 bin，再由 Bundle 加载。探针还使用 Gensim 自带 save/load 检验，二者都留有预测证据。只保存词向量不能恢复 SVM/IDF 的完整分类流水线，也不能继续恢复全部训练状态。

FastText 的原生 bin 带 magic、文件格式版本、参数、字典和矩阵。本工程没有用 Gensim 去载入监督分类 bin，因为 Gensim 的子词向量 API 不提供等价监督标签分类器；两个格式与两条路线独立使用。

## 实验的解释边界

版面 ID 是真实版面位置，不是人工审核的主题；同主题可能出现在多个版面，同一版面也可能含多个主题。文章标题保留，有助于分类但也可能带版面特有栏目词。随机一月分组划分不能代替真正未来部署，因此补充冻结模型逐月评估。

单因素实验只检验围绕基线的一次改变，没有探索全部交互组合。大量配置共用一个验证集，有选择偏差的可能；最终测试集按选定配置后统一评估并报告三种子标准差。这里的证据支持当前语料和实现，不把论文在不同数据集的表现当成本项目结果。
