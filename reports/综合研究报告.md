# FastText 论文与实现分析及 Gensim 文本向量化表示学习实验报告

<a id="abstract"></a>

## 摘要

本文围绕上手 Gensim 与理解 FastText 两项目标，以 Bag of Tricks for Efficient Text Classification 为第一章的解读对象，整理论文要点、核心源码、文本向量化实验、实现差异及参数对照。已执行实验使用人民日报 1998 年一月至六月文本：清洗后保留 18,108 篇，一月 3,050 篇按近重复组隔离后划分为 2,138/456/456 篇训练、验证和测试文章。类别来自版面编号 01–12，不是人工标注的主题。五种 Gensim 表示均连接统一的 LinearSVC，另以多数类和原生监督 FastText 为参照；表示与分类器仅拟合训练集，选参仅使用验证集，人民日报历史实验采用三个种子和单线程；当前默认使用 20 个训练线程。

一月 12 类主配置中，TF-IDF 测试 Macro-F1 为 0.4652，Gensim FastText 为 0.4127 ± 0.0122；WordSim-240 上 Word2Vec 与 Gensim FastText 的 Spearman rho 分别为 0.3207 ± 0.0090 和 0.4610 ± 0.0101，显示词相似度与版面分类排序不同。补充优化后的原生 FastText 达到 0.4656 ± 0.0020，但日期成对抽样的差值区间包含零，不能确认其稳定优于 TF-IDF。源码与数值核验说明 HS score 的解释限制。

第二部分使用原论文八套分类数据和完整 YFCC100M 文本数据，开展原生监督 FastText 与 Gensim 两阶段近似路线的对照。全量进度和已完成结果单独列出，未完成的配置不作为最终结论。逐运行、逐类、逐关系、逐轮和逐篇明细保存在 CSV，正文展示支撑结论的汇总与趋势。

另以清华 THUCNews 全量语料开展独立词向量实验，遍历 836,075 篇，清洗后保留原有 5,000 篇留出文章，其余训练。重新训练 TF-IDF、Word2Vec、FastText，统一做最近类别中心诊断；词向量另与此前 5 万篇结果对照，训练使用 20 个线程，实际完成数量和结果列在 4.9 节。此前原论文全量复现已经按用户要求停止。

关键词：FastText；Gensim；子词表示；文本向量化；版面分类；参数比较

## 一、FastText论文解读

本章解读 *Bag of Tricks for Efficient Text Classification*，依据 [paper 目录中的论文](../paper/Bag%20of%20Tricks%20for%20Efficient%20Text%20Classification.pdf)（arXiv v3，2016）。论文用简单模型实现高效文本分类，主要优化了文本表示、局部词序特征和类别计算。

<a id="paper-background"></a>

### 1.1 研究目标

作者希望在保持分类效果的同时，降低训练和预测成本，尤其适用于大语料、类别多的任务。思路是以词袋加线性分类器为基础，通过几项优化获得接近复杂模型的效果。

<a id="classification-paper"></a>

### 1.2 平均表示与参数共享

模型先将词和词 n-gram 映射为向量，再取平均得到文本表示，最后用线性输出层预测类别：

$$
\mathbf h=\frac{1}{n}\sum_{i=1}^{n}\mathbf v_i.
$$

其中 $n$ 是输入特征数，$\mathbf v_i$ 是第 $i$ 个特征的向量。平均操作计算简单，适合快速处理长文本。

输入特征先映射到低维空间，再映射到类别，相当于把一个大权重矩阵拆成两个矩阵。不同类别共享特征表示；隐藏维度足够低时，还能减少参数量。这就是论文所说的低秩分类器。

<a id="paper-objective"></a>

### 1.3 联合训练与多核优化

特征向量和分类参数一起训练，标签误差直接影响文本表示，使向量更适合分类。训练采用随机梯度下降，学习率随进度线性降低，并通过多 CPU 线程异步更新提高速度。

<a id="paper-hierarchical-softmax"></a>

### 1.4 层次 softmax：减少类别计算

普通 softmax 要计算全部类别。论文用 Huffman 二叉树组织标签，训练时只更新真实标签所在的路径，把输出计算从类别数 $K$ 的量级降到约 $\log_2 K$ 的量级。频繁标签路径更短；预测时还可剪去概率较低的分支。类别越多，这项优化越有价值。

<a id="paper-ngram-features"></a>

### 1.5 词 n-gram 与哈希：补充词序、控制存储

词向量平均会丢失词序。例如“狗 咬 人”和“人 咬 狗”包含相同的词，却表达不同意思。加入相邻词的 bigram 后，“狗 咬”和“人 咬”成为不同特征，模型就能利用局部顺序。

为避免逐一维护大量词组合，论文把词 n-gram 哈希到固定数量的桶中，控制特征表规模。代价是不同组合可能落入同一桶、共享参数。这里的 n-gram 指相邻词组合。

<a id="paper-experiment-results"></a>

### 1.6 实验设置与结果

原论文结果如下，数值来自 PDF 第 3 页表 1 和第 4 页表 5。

| 任务 | 设置 | 结果 |
| --- | --- | --- |
| 八个文本分类数据集 | 10 维，5 轮；验证集选择学习率 | 加入 bigram 后，Accuracy 提高 0.3–4.4 个百分点 |
| YFCC100M 文本标签预测 | 约 31 万标签，50 维 bigram，5 轮 | P@1 为 36.7%；训练 7 分 47 秒，测试 50 秒 |

<a id="paper-critical-review"></a>

### 1.7 贡献与局限

论文将平均表示、参数共享、词 n-gram、哈希和层次 softmax 组合起来，使简单分类器具备较强效果和大规模处理能力。它适合作为高效文本分类基线，但平均表示与局部词组合难以充分捕捉长距离依赖和复杂语义，原文结果也没有全面超过深度模型。

## 二、FastText复现

<a id="reproduction-protocol"></a>

### 2.1 数据与实现

本部分使用原论文的八套分类数据和完整 YFCC100M 文本标签数据，保留作者提供的训练、验证及测试划分。原生 FastText 使用监督训练；Gensim FastText 先学习无监督词向量，再用平均文章向量接分类器，属于原数据上的近似复现。Gensim 的字符子词与原生的词 bigram 是不同特征，结果分开解释。

分类实验采用 10 维、5 轮，原生学习率沿用作者公布的选参结果；Gensim 使用 CBOW 与固定 C=1 的 LinearSVC。标签实验采用 50/200 维、5 轮，原生使用层次 softmax；Gensim 接外部 Huffman 分类头，可用时由 CUDA 训练，预测采用精确树搜索。正式训练使用种子 42、2026、7；本章经用户批准使用 20 个 CPU 训练线程，全项目已取消单线程约束，历史结果保留实际线程数。多线程更新不保证逐位确定性，三种子均值与样本标准差衡量训练波动，不构成显著性检验。预测单线程；本机、实现版本和计时范围与论文不同，耗时不直接视为论文速度的复现。

来源：[原论文](../paper/Bag%20of%20Tricks%20for%20Efficient%20Text%20Classification.pdf)、[作者分类脚本](https://github.com/facebookresearch/fastText/blob/v0.9.2/classification-results.sh)、[官方 YFCC 数据入口](https://fasttext.cc/docs/en/dataset.html)、[运行配置](../configs/paper_reproduction.yaml)。

协议差异：本轮原生模型依照论文使用层次 softmax；归档 v0.9.2 分类脚本采用默认 softmax、4 线程及随机打乱行序。本轮固定原始行序、使用 20 线程，学习率沿用该脚本公布的值。这些差异与版本差异均可能影响结果；全量数据和任务指标对齐，不等于历史数值逐项一致。

能力与计时边界：Gensim 4.4.0 的 FastText 实现对应子词词向量论文，没有 `train_supervised`，且不支持 `word_ngrams != 1`。本机已核查编译内核，实际训练使用 `corpus_file` 和 20 个线程。当前两条路线的耗时比较反映不同训练方案的成本，不能用于认定哪个框架更快；同算法速度基准应对照原生 `train_unsupervised`。依据：[Gensim 4.4.0 源码](https://github.com/piskvorky/gensim/blob/4.4.0/gensim/models/fasttext.py)、[原生训练 API](https://fasttext.cc/docs/en/python-module.html)。

## 三、FastText核心代码阅读笔记

<a id="source-entry"></a>

### 3.1 阅读对象与调用入口

阅读以归档 fastText v0.9.2 的 C++ 核心为主，并与实际 Python 调用和 Gensim 对照。[Python train_supervised](../references/sources/fastText-0.9.2/python/fasttext_module/fasttext/FastText.py) 将参数传入 [pybind](../references/sources/fastText-0.9.2/python/fasttext_module/fasttext/pybind/fasttext_pybind.cc)，绑定释放 GIL 后调用 C++ 训练。核心路径为词典读入与特征构造、模型创建、trainThread、supervised/skipgram/cbow、Model::update、输出损失及参数更新。上游阅读副本不等于对第三方 Windows wheel 的逐字节源码认证。

<a id="subword-code"></a>

### 3.2 字符子词与兼容哈希

[Dictionary::computeSubwords](../references/sources/fastText-0.9.2/src/dictionary.cc) 从带词首、词尾标记的字符串提取片段。代码跳过 UTF-8 后续字节，并在增加片段长度时吸收完整字符，因此中文按字符边界计数；只包含边界标记的一元片段排除。训练词保留整词参数行，字符片段再映射到桶，体现子词词表示研究中的参数共享。

Dictionary::hash 先把每个字节转为 int8，再异或到 uint32 并乘以 16777619，按 32 位溢出。这个有符号字节规则用于兼容历史模型，不能直接用 Python hash() 或另一种无符号字节实现代替。中文、ASCII 和新词的子词/哈希探针均与独立复算一致，完整列表移入 CSV。

<a id="feature-code"></a>

### 3.3 词组合特征与隐藏表示

Dictionary::addWordNgrams 对相邻词的哈希递推，再映射到桶。它对应分类论文的词组合特征；关闭字符子词并不关闭词 bigram。未知词仍可能参与词组合哈希，因此单词 OOV 向量覆盖不能代替整个监督输入的覆盖。Python 参数入口在 wordNgrams≤1 且 maxn=0 时把实际 bucket 设为 0，解释了 unigram 模型体积显著小于 bigram 的现象。

[Model::computeHidden](../references/sources/fastText-0.9.2/src/model.cc) 的核心代码如下，先累计输入特征所在行，再按特征数平均；输入为空时 Model::update 会提前返回。

```cpp
hidden.zero();
for (auto it = input.cbegin(); it != input.cend(); ++it) {
  hidden.addRow(*wi_, *it);
}
hidden.mul(1.0 / input.size());
```

Model::update 随后调用损失的 forward，获得输出参数更新及隐藏梯度，再更新输入矩阵各行；normalizeGradient_ 启用时还按输入特征数缩放梯度。这说明监督路线的表示参数会受到标签反馈。

<a id="objective-code"></a>

### 3.4 监督目标与无监督目标的分派

[FastText::createLoss/supervised](../references/sources/fastText-0.9.2/src/fasttext.cc) 选择负采样、层次 softmax、普通 softmax 等输出目标。supervised 在没有标签或特征时返回；除 OVA 分支外，从文章标签中选目标并调用 Model::update。当前单版面文章只有一个标签，使用 softmax。无监督 skipgram/cbow 则预测词上下文，输出目标不是版面标签。

监督模式下 Dictionary::discard 返回 false，无监督的高频下采样不能直接套用到监督分类。NS/HS 改变输出事件和运算路径；Gensim 的 HS 对照明确设 hs=1、negative=0，避免同时训练两个目标。对应的分类与内在评价在第四、六部分分别报告。

<a id="training-code"></a>

### 3.5 学习率、线程、矩阵与模型保存

FastText::trainThread 按 `tokenCount/(epoch×ntokens)` 计算进度，学习率为 `lr×(1−progress)`；局部 token 计数超过 lrUpdateRate 才上报共享进度。训练根据模型类型调用 supervised、cbow 或 skipgram，多个线程共享输入/输出矩阵，更新顺序会变化。本节历史结果使用 thread=1；当前运行默认 thread=20，历史数据不改写为多线程结果。

[DenseMatrix](../references/sources/fastText-0.9.2/src/densematrix.cc) 按连续行存储参数。输入矩阵通常为 `(词数+桶数)×维度`，普通 softmax 输出矩阵为 `类别数×维度`。saveModel/loadModel 保留字典、参数和矩阵；只保存词向量不足以恢复分类输出头。原生小语料训练 P@1=1，保存加载预测一致，支持分类链路正确运行，但不能据此推断正式泛化质量。

<a id="engineering"></a>

### 3.6 运行探针与工程核验

已完成子词/哈希、OOV 聚合、最低词频、高频下采样、可重复迭代、真实任务与学习率、数组类型和保存加载探针。关闭下采样与 sample=0.001 的小语料有效训练词数分别为 6,000 和 501，说明下采样改变训练事件而不从分类文章中删除功能词。Gensim 已登录词聚合最大复算误差为 1.86e-09，OOV 聚合最大误差为 0；可生成的 OOV 向量未必具有正确语义。

数据深度核查独立重算清洗链路、词典文档频率、IDF、预测标签和各项指标。对 163,940,778 对文章的 SimHash 全对检查与生产索引得到同样的 3 对近重复；这只验证指定距离阈值，不证明所有语义重复均已识别。323 个完整预测分区重载最大分数差为 0；一月 12 类 seed 42 的七种方法独立重训后，完整验证预测 CSV 字节一致。这些结果限定于当前机器、固定依赖及单线程，不保证跨平台逐位一致。

缓存核对模型、输入、分区、预测与 SHA-256，异常缓存保留后重建；操作系统文件锁保护写入。公开预测检查包括空文本、标点、分词空白、全 OOV 和旧协议拒绝。Doc2Vec 原推断依赖文章编号，修正前 20 篇探针中有 1 篇标签改变；当前由 token 序列 SHA-256 重置推断种子，全 OOV 文章置零，并重训受影响的主矩阵、冒烟和日期隔离运行。当前适配器见[content_seed.py](../gensim_lab/content_seed.py)。

### 4.2 表示训练与文章向量构造

| 方法 | 本项目训练或拟合 | 文章向量 |
| --- | --- | --- |
| TF-IDF | 训练词典、文档频率与 log2(N/df) IDF | 稀疏词袋与 L2 归一化 |
| LSI | 训练 TF-IDF 矩阵的随机截断低秩投影 | 至多 100 维与 L2 归一化 |
| Word2Vec | 主配置 Skip-gram 负采样，保持句子/段落边界 | token 频次均值，跳过 OOV，再 L2 归一化 |
| Doc2Vec | DBOW，dm=0、默认 dbow_words=0 | 所有分区内容种子推断 30 轮；全 OOV 置零 |
| Gensim FastText | Skip-gram，整词与字符子词共享上下文目标 | 组合词向量均值或训练 IDF 加权，再 L2 归一化 |

文章聚合为 `z(d)=Σ w(t,d)v(t)/Σ w(t,d)`，主配置权重为 token 频次；加权对照再乘训练 IDF，词典外可生成向量的词使用训练最大 IDF。无有效词向量时输出零向量。词向量上下文不跨文章，超长片段最多 1,000 词；SentenceCorpus 每轮可重新遍历。Doc2Vec 默认未联合训练词向量，不把其词向量作为有效词语义模型。代码入口见 [models.py](../gensim_lab/models.py)，当前 Doc2Vec 运行另使用第三部分所述内容种子适配器。

TF-IDF 沿用同一训练集拟合的统计模型：文档频次至少 3、最高占比 0.9、至多 50,000 词，log2(N/DF)，L2 归一化。其结果与训练设置未改变，可直接复用。Word2Vec 与 FastText 分别从头训练原生 Gensim 模型：CBOW、100 维、窗口 5、最低词频 5、HS=1/negative=0、下采样 0.001。FastText 使用字符子词 1–3、200,000 桶。两个模型各使用 20 个 CPU 训练线程，数值库 4 线程；固定种子 42、输入顺序和 Python hash seed=0。多线程更新不保证逐位确定性；每个模型仅一次正式训练（n=1），不报告重复实验误差或显著性。

#### 搜索、复验与冻结规则

1. 种子 42 运行两个模型各 6 组，共 12 次，搜索阶段只计算验证指标。
2. 每个模型在五个新方案中选验证分最高者；与 CBOW＋HS 基线各补 2026、7 两种子，共增加 8 次训练。
3. 对基线和新方案分别计算三个种子的验证均值与样本标准差（ddof=1），按均值选最终训练方式。完全同分时优先基线，初筛新方案同分按配置名称稳定排序。

#### 逐轮验证、上升判断与检查点

先训练 3 轮。“仍明显上升”具体定义为：当前主指标相比上一轮或两轮前增幅 **>0.001**。第 3 轮若两种增幅均未达阈值，停止该配置；仍上升则继续。随后当最佳有效提升参照连续 3 轮未提高超过 0.001，且最近一轮和两轮均无上升时停止，最多 15 轮。0.001 是计算预算规则，不代表统计显著性；仍有上升趋势的恢复曲线不会仅因落后于历史峰值被停止。所有轮次中实际最高验证分都能成为最佳检查点，即使增幅小于阈值。

学习率按最多 15 轮从指定 alpha 线性降至 0.0001；早停不重排已用学习率。Word2Vec、FastText 分别判断上升并分别选轮数，不强制使用相同 epoch。每轮保存原生检查点、逐题评价、Pearson、Spearman、类比正确率、覆盖率、耗时和上升/停止理由。不记录训练 loss；最终选中模型重载后重新验证，核对预测指标一致。

### 4.12 THUCNews 向量维数搜索

#### 实验设计

在固定 50,000 篇、23,080,089 词训练子集上，比较 50、100、150、200、300 维。Word2Vec 固定 Skip-gram＋NS5、初始学习率 0.025；Gensim FastText 固定 Skip-gram＋NS10、初始学习率 0.05。每档均完成种子 42、2026、7，共 30 组结果；100 维六组经封存核验后复用，其余 24 组从头训练。窗口、最低词频、下采样、子词和线程设置沿用前述搜索，词表及主验证词对保持一致。

各次运行通过逐轮 WordSim240 验证 Spearman 独立选择最佳检查点，至少 3 轮、最多 15 轮，停止规则及线性学习率日程沿用学习率阶段。第 3 轮若当前得分相对前一轮与前两轮均未提高超过 0.001，即停止；此后若连续 3 轮未形成有效提升，且最近一至两轮也无超过 0.001 的增幅，则停止。任何严格更高的得分均更新最佳检查点，0.001 仅作为停止规则的增幅阈值；学习率按 15 轮上限线性降至 0.0001，提前停止不重新缩放日程。主指标使用相同的 92 个词表内词对，验证集共 95 题。维数选择依据三次运行的验证均值，精确同分时优先较低维数。下述误差均为样本标准差（n=3），反映固定题目下的训练波动，未进行显著性检验。

## 五、对比Gensim的实现方法

<a id="gensim-methods"></a>

### 5.1 五种 Gensim 表示的实现差异

| 方法 | 核心实现 | 输入与词表 | 适用及限制 |
| --- | --- | --- | --- |
| TF-IDF | Dictionary/TfidfModel | 文档频率过滤、稀疏词袋 | 保留栏目关键词；不直接学习词语义 |
| LSI | LsiModel 随机低秩投影 | 训练 TF-IDF 矩阵 | 压缩共现结构；投影秩受词表与样本数限制 |
| Word2Vec | Word2Vec + word2vec_inner Cython | token 频次词表、句子上下文 | 上下文词表示；跳过 OOV，文章聚合丢失顺序 |
| Doc2Vec | Doc2Vec + doc2vec_inner DBOW | TaggedDocument，推断需已登录词 | 文章表示；需固定内容种子与统一推断协议 |
| Gensim FastText | FastText + fasttext_inner Cython | 整词表、字符子词哈希桶 | 共享片段及 OOV 组合；桶体积大，可生成不等于语义正确 |

TF-IDF no_below 统计文档频次，Word2Vec/FastText min_count 统计 token 频次，两套词表不完全相同。文档频率过滤、训练上下文目标与监督目标的差异都是实现条件，不能把整个流水线的分数差当成某个单一机制的因果效应。训练集词典、IDF 和表示隔离已由独立核查确认。

<a id="fasttext-comparison"></a>

### 5.2 Gensim FastText 与原生监督 FastText

| 比较 | Gensim FastText + LinearSVC | 原生 FastText 监督分类 |
| --- | --- | --- |
| 表示学习目标 | 词到上下文；无监督，只用当前训练文章 | 文章到版面标签；监督 |
| 子词 | 主配置字符 1–3；词内 UTF-8 字符片段 | 主配置关闭字符子词，保留词 bigram |
| 文章表示 | 训练完词向量再均值/IDF 加权、L2 归一化 | 内部输入特征平均；不采用本项目的外部 L2 流程 |
| 分类器 | 独立训练的类别权重 LinearSVC，验证选择 C | 标签输出矩阵与输入矩阵联合训练，softmax |
| 输出分数 | SVM 决策边距 | softmax 近似概率；源码存在数值平滑，不视为校准概率 |
| OOV | 通过哈希子词生成向量，可能包含未训练桶 | 单词字符向量关闭时无 OOV 单词向量；含未知词的词 bigram 仍可能产生哈希特征 |

Gensim 训练更新 vectors_vocab 和 vectors_ngrams，adjust_vectors 在查询前组合整词与子词。已登录词取整词行加子词行的平均，OOV 只平均片段桶，重复桶可以重复贡献。判断训练词表应查询 key_to_index；启用子词时 `word in wv` 可对 OOV 返回真。关闭子词后 OOV 查询抛 KeyError，文章聚合器跳过；未训练桶仍有初始化值，不能以非零向量声称语义已学会。

Gensim 默认负采样频次指数为 0.75，与子词词表示论文的 0.5 不同；训练更新按队列任务调度，通过 _do_train_job 调用 train_batch_any，在 nogil 区域执行。batch_words 是任务大小，不等于平均梯度 mini-batch。原生监督直接通过标签更新输入/输出矩阵，当前无额外类别重加权；Gensim 表示连接 balanced SVM。因此相同轮数不代表相同预算，二者比较的是完整路线。

Gensim 模型及词典可原生保存，完整分类另需 Bundle 中的 IDF/SVM；原生监督用 native.bin。Gensim 的子词向量 API 不提供等价监督输出头，没有用它载入监督分类 bin 进行相同预测。

### 5.3 句子上下文评分接口及数值限制

Word2Vec 的 score 只支持相应 HS 配置，逐句分数为局部上下文对数项之和。内核跳过 OOV，移除后重建窗口，使用 log-sigmoid 查表并跳过 |logit|≥6 的饱和节点。固定审计句的稳定复算差在 SG 可达 78.1978、CBOW 测试可达 6.9706，近似误差需独立解释。不能取 exp 后称为规范句子概率，也不能直接称为语言模型困惑度。
